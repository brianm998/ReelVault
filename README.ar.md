# ReelVault

تطبيق متعدد المنصات لفهرسة الفيديو مستوحى من Lightroom — تصفح سريع وأصيل لمكتبات الفيديو الكبيرة.

**ReelVault مخصص لتنظيم الفيديوهات واكتشافها وإدارتها. إنه ليس محرر فيديو.**

## نظرة عامة

يساعدك ReelVault على:

- **التصفح** من خلال آلاف الفيديوهات في شبكة متجاوبة ومحسّنة مع إمكانية ضبط حجم الصور المصغرة.
- **الاستعراض** بأسلوب Lightroom: مرّر المؤشر فوق الصورة المصغرة واسحب يساراً↔يميناً لمعاينة الإطارات عبر الجدول الزمني.
- **التجميع** لمتغيرات ذات صلة (مثل تصدير 4K و1080p من المصدر نفسه) في مجموعات بأسلوب Lightroom؛ مع إمكانية تعيين أحدها مفضلاً للشبكة والفتح.
- **اكتشاف** المحتوى من خلال البحث النصي الكامل وتصفية الوسوم وقوائم التصفية لكل حقل (الكاميرا، العدسة، الترميز، سنة التصوير، الكلمة المفتاحية).
- **فحص** البيانات الوصفية التفصيلية: الترميز، الدقة، معدل الإطارات في الثانية، معدل البت، فضاء اللون، HDR، EXIF، GPS، نموذج الكاميرا/العدسة.
- **التنظيم** بملاحظات حرة وكلمات مفتاحية وعمليات متعددة الاختيار.
- **تسليم** المقاطع إلى محررات خارجية عبر السحب والإفلات — اسحب بطاقة أو أكثر مباشرة من الشبكة إلى DaVinci Resolve أو Final Cut Pro أو Premiere Pro أو أي تطبيق يقبل إفلات الملفات.
- **سير عمل متعدد الفهارس**: فتح/إغلاق/تبديل فهارس SQLite من قائمة الملفات، مع قائمة بالفهارس الأخيرة وعناوين نوافذ لكل فهرس.

## البنية المعمارية

```
Desktop / macOS clients          iOS client (iPhone / iPad)
   ↓ gRPC over loopback             ↓ gRPC + HTTPS media over the LAN
   │                                │ (mDNS discovery · pinned TLS · paired)
   └───────────────┬────────────────┘
                   ↓
        Rust Backend Daemon (reelvault-core)
                   ↓
        SQLite Catalog + FFmpeg/FFprobe + Filesystem
```

- **نواة Rust** (`core/`) — خادم gRPC مبني على Tonic. يتحكم في فهرس SQLite، واستخراج البيانات الوصفية عبر FFprobe، وإنشاء الصور المصغرة وإطارات الاستعراض، والمسح والفهرسة، والبحث، وتجميع الفلاتر. يدعم تبديل الفهرس النشط أثناء التشغيل عبر RPCs: `OpenCatalog` / `CloseCatalog` / `GetCurrentCatalog`، بحيث تستطيع عملية خادم واحدة خدمة مكتبات متعددة طوال دورة حياتها.

- **عميل Kotlin Compose لسطح المكتب** (`kotlin-desktop/`) — واجهة Compose Multiplatform. يكشف تلقائياً عن خادم جارٍ على `127.0.0.1:50051`؛ إذا لم يكن هناك خادم، يشغّل الخادم المدمج بنفسه (مع الرجوع إلى منفذ يعينه نظام التشغيل في حال كان 50051 مشغولاً).

- **عميل SwiftUI macOS** (`macos/`) — تطبيق macOS أصيل مكافئ للميزات، مع نفس التدفق التلقائي للإطلاق، وقائمة ملفات حقيقية لـ macOS (مجموعة Commands)، وعنوان نافذة متفاعل يتتبع الفهرس المفتوح.

- **عميل SwiftUI iOS** (`ios/`) — تطبيق iPhone / iPad **عن بُعد حصراً**. لا يمتلك وصولاً للملفات المحلية ولا يحتوي على خادم مدمج: يكتشف الخادم عبر Wi‑Fi (mDNS)، ويتصل عبر قناة TLS مثبتة ببصمة الأصابع بعد إقران لمرة واحدة، ويتصفح عبر gRPC، و**يبث** الفيديو (HLS مخفض الدقة) من خادم الوسائط. يستبدل سحب المحرر بصفحة مشاركة iOS ويضيف رفعاً من الصور / الملفات. راجع [`ios/README.md`](ios/README.md).

- **ReelVaultKit** (`kit/`) — حزمة SwiftPM محلية من كود Swift المشترك المستخدم من قبل **كلا** عميلَي Apple: النماذج، نماذج العرض، عميل gRPC، الاكتشاف، TLS المثبت، وطبقة التخزين المؤقت/البث للوسائط.

- **فهرس SQLite** — قاعدة بيانات بوضع WAL مع FTS5 للبحث النصي الكامل. المخطط موجود في [`core/schema.sql`](core/schema.sql).

> **الصور المصغرة لـ ProRes RAW محسّنة على macOS فقط.** لا يستطيع ffmpeg تطوير ProRes RAW (Atomos S-Log3 / S-Gamut)، لذا على **macOS** يفكّ الخادم ضغطها عبر QuickLook / AVFoundation — مع ألوان صحيحة واستعراض حقيقي لكل إطار. أما على **Linux / Windows** فلا يوجد مثل هذا المفكك، فيعود الخادم إلى ffmpeg: إطارات أفتح/أغمق وإطار استعراض مكرر واحد. النواة Rust تُبنى بشكل متطابق على المنصات الثلاث — لا يرتبط AVFoundation بها أبداً. التفاصيل في: [`core/README.md`](core/README.md) (مسارات البناء والفك) و[`macos/README.md`](macos/README.md) (عميل macOS). كل الترميزات الأخرى تعالجها ffmpeg بنفس الطريقة في كل مكان.

## حالة المشروع

**الإصدار الأولي (MVP) يعمل على macOS وCompose Desktop.** كلا العميلين يوفران نفس مجموعة الميزات؛ يضيف عميل macOS أوامر شريط القائمة الأصيلة وإطلاق المحررات عبر NSWorkspace. **عميل iOS عن بُعد حصراً** (iPhone / iPad) يتصل بخادم عبر الشبكة المحلية ويبث الفيديو — تصفح، فحص، تجميع، مشاركة، ورفع؛ راجع [`ios/README.md`](ios/README.md).

### ✅ مكتمل

**النواة**
- [x] خادم gRPC مع سطح RPC كامل (فيديوهات، بحث، مسح، وسوم، مجموعات، مجموعات مكدسة، فلاتر، حالة، إعداد، دورة حياة الفهرس).
- [x] فهرس SQLite بوضع WAL + FTS5؛ تبديل الفهرس أثناء التشغيل عبر `OpenCatalog` / `CloseCatalog`.
- [x] استخراج البيانات الوصفية عبر FFprobe (ترميز، دقة، FPS، معدل البت، HDR، EXIF، GPS، كاميرا/عدسة).
- [x] إنشاء الصور المصغرة وإطارات الاستعراض بأسلوب Lightroom (10 إطارات لكل فيديو) مع أقفال لكل فيديو لتجنب تكرار العمل.
- [x] تقليص FFmpeg المتزامن (يعتمد افتراضياً على عدد أنوية المعالج) لمنع الإجهاد الزائد على التخزين المدعوم بـ SAN أثناء مسح المكتبات الكبيرة.
- [x] مسح المكتبة مع اختيار التكرار التلقائي وتجميع المتغيرات.
- [x] أعلام سطر الأوامر لـ `--db-path` و`--no-catalog` و`--port` (مع الرجوع إلى منفذ يعينه نظام التشغيل)، وسطر `REELVAULT_LISTENING_ON=…` على stdout قابل للتحليل من قِبل مشغّلات العميل.

**كلا العميلين**
- [x] عرض شبكة محسّن مع عدد أعمدة تكيفي وشريط تمرير حجم الصورة المصغرة.
- [x] معاينة الاستعراض عند التمرير فوقها، تراكب التشغيل عند التمرير، تحديد متعدد مع نطاق Shift و⌘/Ctrl للتبديل.
- [x] واجهة المجموعات المكدسة: شارات مع عداد الأعضاء، نقر للتوسيع، نجمة لتعيين المفضل، أزرار فتح لكل عضو.
- [x] الألواح الجانبية: مواقع المكتبة (يسار)، التفاصيل + البيانات الوصفية + الملاحظات + الكلمات المفتاحية (يمين). علامات التبويب تتحكم في كليهما، وعلامات السهم المنفردة تطوي كل منها.
- [x] قوائم منسدلة للفلاتر في الشريط العلوي (كاميرا / عدسة / كلمة مفتاحية / ترميز / سنة) — يظهر فقط الحقول التي تحتوي على بيانات؛ مجموعة بـ AND مع البحث.
- [x] قائمة ترتيب بجميع الحقول الرئيسية (اسم الملف، التواريخ، المدة، الحجم، الدقة، fps، الترميز، معدل البت، الكاميرا، العدسة، الكلمة المفتاحية)؛ انقر مرة أخرى لعكس الاتجاه.
- [x] إدارة الوسوم/الكلمات المفتاحية: أنشئها أثناء التشغيل، طبّقها على تحديد متعدد، فلتر الشبكة بالنقر على السهم `>`.
- [x] قائمة سياق بالنقر اليمين على كل بطاقة: فتح بالمشغل الافتراضي والكشف في Finder/Explorer — تعمل على التحديد الكامل متعدد العناصر.
- [x] تسليم بالسحب والإفلات: اسحب البطاقات المحددة إلى أي تطبيق يقبل إفلات الملفات (DaVinci Resolve، Final Cut Pro، Premiere Pro، إلخ).
- [x] تدفق متعدد الفهارس: قائمة الملفات مع فتح / إغلاق / فتح الأخير، صفحة "فتح فهرس" عند الإطلاق الأول، قائمة مستمرة بالأخيرة، عنوان نافذة يعرض اسم الفهرس المفتوح.
- [x] الإطلاق التلقائي للخادم المدمج (مع الرجوع عند انشغال المنفذ) عند عدم وجود واجهة خلفية تعمل عند بدء التشغيل.
- [x] نصوص مساعدة عند التمرير (تلميحات في Kotlin عبر `TooltipArea`؛ وفي SwiftUI عبر `.help(_:)`) على كل عنصر تفاعلي وحقل بيانات وصفية.
- [x] الوضع الداكن افتراضياً؛ خيار التبديل بين الفاتح والداكن.

## البداية

### المتطلبات الأساسية

- **Rust** (يُنصح بالإصدار 1.75+) — لبناء خادم النواة.
- **FFmpeg / FFprobe** — يجب أن يكون على `PATH`. يُستخدم لاستخراج البيانات الوصفية وإنشاء الصور المصغرة/إطارات الاستعراض.
- **JDK 17+** + Gradle (غلاف مضمّن) — لعميل Kotlin لسطح المكتب.
- **Swift 5.9+ / Xcode 15+** — لعميل macOS.
- **Xcode 16+ (iOS 18 SDK) + [XcodeGen](https://github.com/yonaskolb/XcodeGen)**
  (`brew install xcodegen`) — لعميل iOS.

راجع [`SETUP.md`](SETUP.md) للحصول على تعليمات التثبيت الخاصة بكل منصة.

### بناء خادم النواة

```bash
cd core
cargo build --release
```

يُحفظ الملف الثنائي في `core/target/release/reelvault-core`. شغّله مباشرة إذا أردت التحكم فيه بنفسك، أو دع أحد العملاء يشغّله تلقائياً عند الإطلاق الأول:

```bash
# الوضع الافتراضي — استخدم الفهرس الافتراضي للمنصة على المنفذ الافتراضي.
./target/release/reelvault-core

# الإطلاق بدون فهرس (يستخدم العملاء هذا الوضع)؛ طباعة المنفذ المرتبط.
./target/release/reelvault-core --no-catalog --port 0

# فتح فهرس محدد عند بدء التشغيل.
./target/release/reelvault-core --db-path /path/to/library.db
```

يطبع الخادم سطراً ثابتاً `REELVAULT_LISTENING_ON=127.0.0.1:N` على stdout يحلّله العملاء لاكتشاف المنفذ المعيّن.

### تشغيل عميل Kotlin Compose لسطح المكتب

```bash
cd kotlin-desktop
./gradlew run
```

عند الإطلاق الأول يستطلع العميل `127.0.0.1:50051` و — إذا لم يكن هناك شيء يستمع — يشغّل الخادم المدمج. ترتيب البحث عن مسار البناء:

1. `$REELVAULT_CORE_BIN` (مسار مطلق لملف الخادم القابل للتنفيذ)
2. ثنائي بجانب ملف jar للتطبيق
3. `core/target/release/reelvault-core` أو `core/target/debug/reelvault-core` في شجرة التطوير
4. `reelvault-core` على `PATH`

للتطوير، فقط نفّذ `cargo build` داخل `core/` وسيتعرف العميل على الثنائي التجريبي.

### تشغيل عميل SwiftUI macOS

```bash
cd macos
swift run
```

نفس تدفق الإطلاق التلقائي، نفس ترتيب البحث عن الثنائي (مع إضافة مسار `Resources/reelvault-core` داخل الحزمة لحزم التطبيق الموقّعة). استخدم `⌘O` لفتح فهرس و`⇧⌘W` لإغلاقه؛ القائمة الأخيرة موجودة تحت `File → Open Recent`.

### تشغيل عميل SwiftUI iOS

عميل iOS هو **عن بُعد حصراً** — يتصل بخادم عبر الشبكة المحلية بدلاً من إطلاق واحد. شغّل الخادم في وضع البُعد على جهاز متصل بنفس Wi‑Fi:

```bash
reelvault-core --remote --db-path /path/to/library.db --import-dir /path/to/imports
```

ثم أنشئ مشروع Xcode (`.xcodeproj` غير مُدرج في المستودع) وابنِه:

```bash
cd ios
make project          # requires XcodeGen: brew install xcodegen
make build            # iOS Simulator; or open ReelVault.xcodeproj to run on a device
```

عند الإطلاق الأول يكتشف التطبيق الخادم عبر mDNS، وتفوّض الجهاز مرة واحدة برمز إقران مكوّن من 6 أرقام (أنشئه من **File → Pair a New Device** في عميل سطح المكتب، أو من سجل الخادم)، ثم تصفح وبث. يتطلب **iOS 18+** و**Xcode 16+**. التفاصيل الكاملة، بما في ذلك نموذج البث والإقران، موجودة في [`ios/README.md`](ios/README.md).
